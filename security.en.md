# Security Policy

The **Ubers** development team takes the security of this project and web application seriously. This document outlines our policy for reporting and handling security vulnerabilities.

---

## 🛡️ Supported Versions

Only the latest version running on the primary branch (`main`) actively receives security updates and bug fixes.

| Version | Supported |
| :--- | :--- |
| **Latest (Main / Live Production)** | ✅ Yes |
| **Past Releases / Legacy Branches** | ❌ No |

---

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability (such as PHP data manipulation flaws, DOM-based script injection via TypeScript, server path exposure, or any other vulnerability):

1. **DO NOT open a public Issue** to report security vulnerabilities.
2. Send the details directly via email to the lead maintainer:
   - **Email:** [shadow.voidh@gmail.com](mailto:shadow.voidh@gmail.com)
   - **Subject:** `[SECURITY VULNERABILITY] - Ubers Web App`

### What to include in your report:
- **Description:** A detailed explanation of the vulnerability found.
- **Steps to reproduce:** Clear instructions or a Proof of Concept (PoC).
- **Potential impact:** What an attacker could achieve by exploiting this flaw.
- **Suggested fix (optional):** If you already have a proposed solution or patch.

---

## ⏱️ Response and Remediation Timeline

- **Acknowledgement:** We aim to respond to your report within **48 hours** confirming receipt.
- **Assessment and Patch:** We will work to validate the vulnerability and release a fix to the `main` branch as quickly as possible.
- **Credits:** If you wish, we will gladly credit your name/profile in the commit notes once the vulnerability has been resolved.

Thank you for helping keep this repository safe! 🚀
